MODULE 02 · DRAFTSHOT

Inside a Tick

One server tick of DraftShot, step by step. Why server-authoritative? Because if clients reported their own positions, any client could lie about where it is — so the server is the only truth.

1. Keyboard deltas 2. Fixed-step loop 3. Shared physics 4. AABB + Ghost Box 5. Authoritative state 6. State to clients 7. First to 5

Step 1: Clients send keyboard-state deltas

Each client sends what keys are pressed — a keyboard-state delta. Nobody sends a position.

All 7 steps (plain list)
  1. Clients send keyboard-state deltas — Each client sends what keys are pressed — a keyboard-state delta. Nobody sends a position.
  2. The server runs its fixed-step loop — The server steps the game forward on a fixed schedule. The loop is the clock everything else follows.
  3. The shared physics module applies the input — The same physics module runs in the browser and on the server, so both sides agree on what an input means.
  4. AABB + Ghost Box collision — Collision is checked with AABB plus Ghost Box, so fast movement does not tunnel through a wall.
  5. The authoritative state is the truth — Whatever the server says the game is, that is the game. A client that disagrees is wrong, not the server.
  6. State goes back to the clients — The server sends the authoritative state back, and every client renders from it.
  7. First to 5 wins the round — The round ends when a player reaches 5. The server decides the score, not the clients.
